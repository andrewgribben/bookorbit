# W1-B6: foliate vs Reactor parity matrix (web reader)

Purpose: give the owner the evidence to decide whether to flip
`VITE_READER_ENGINE=reactor` to be the default for the web EPUB reader.

Scope: BookOrbit web only (`client/src/features/reader`), EPUB engine swap
(`useFoliate.ts` vs `useReactor.ts`, wired in `ReaderView.vue:904`). PDF, CBZ,
DJVU and audiobook readers are unaffected by this flag and are out of scope.

Sources: `D:/Development/reactor/docs/plans/W1.md` (row W1-B6, gap list
R-G1..R-G7, section 9 coordinator decisions), `D:/Development/reactor/docs/hosts/web.md`,
this repo's `AGENTS.md`, `client/src/features/reader/epub/composables/useReactor.ts`
(header comment is the authoritative current gap list), `useFoliate.ts`,
`ReaderView.vue`, `media-overlay/`, `features/tts/`.

No format for an Android "A2" matrix exists yet in either repo (A2 is listed in
`docs/PLAN.md` as a pending owner device session, not yet written up) and no
`A2`/parity-matrix markdown file exists in `D:/Development/reactor/docs`, so
this matrix's shape was authored from scratch against this card's own
column/book-type spec.

## Matrix

Status legend: **parity** (same behaviour or an equivalent path), **gap**
(Reactor lacks a capability foliate has, with a documented fallback or
no fallback), **regression** (Reactor is wired but behaves differently in a
way that changes user-visible outcome), **untested-needs-owner** (code review
only, no automated or scripted check possible from this worktree).

Representative book types used for classification: **reflowable** (plain
EPUB3, flowing text), **fixed-layout** (`rendition:layout=pre-paginated`),
**media-overlay** (embedded SMIL/audio narration), **large lazy-loaded EPUB**
(any book opened through the streaming/Range path rather than a full-file
fetch).

## Gaps and regressions summary

Counted directly from the matrix's 53 data rows (a row whose cell carries two
labels, e.g. "parity, **untested-needs-owner**", is counted once in each
bucket below, so the bucket totals sum to more than 53):

- **parity**: 34 rows are a clean match or an equivalent mechanism with no
  behaviour change.
- **gap**: 12 rows (fixed-layout restore tier; media-overlay
  `mediaOverlaySectionIndex` resume tier; scrolled-flow swipe gesture;
  mobile-tap-always-toggles heuristic; `getLocationContext`; publisher
  font-size scaling; fixed-layout spread override, listed once in the
  Settings table and once in the Fixed-layout table since it is one gap
  visible from two feature angles; media-overlay resume heuristics parity
  check (R-G6); TTS resume-position lookup; selection-interaction-start
  signal; fixed-layout detection itself).
- **regression**: 3 rows (fixed-layout books not forced to paginated flow;
  keyboard page-turn missing entirely, listed once in the Keyboard table and
  once in the Accessibility table as "keyboard-only operability" since it is
  one bug visible from two angles).
- **untested-needs-owner**: 6 row-mentions (3 rows are purely
  untested-needs-owner: double-tap debounce, the Range/200-fallback probe
  behaviour, screen-reader/focus behaviour; 3 more rows are parity-with-a-
  caveat: CFI-resolution-failure fallback, cross-engine `time` field
  agreement, Kobo location fields against a real device).
- 1 row (RTL tap-zone mirroring) does not fit any bucket cleanly: it is a
  pre-existing **foliate** gap, not a Reactor regression, so it is noted
  separately rather than counted against Reactor.

Gaps/regressions list (file:line):

1. **Regression - keyboard page-turn missing under Reactor.** No ArrowLeft/ArrowRight/PageUp/PageDown/Space handling anywhere when `VITE_READER_ENGINE=reactor`. `useFoliateInput.ts:350-383` (foliate's source of this behaviour) has no counterpart in `useReactor.ts` or `ReaderView.vue`. This is a real bug, not fixed per this card's instructions.
2. **Regression - fixed-layout books are not forced to paginated flow under Reactor.** `isFixedLayout` is hardcoded `false` in `useReactor.ts:107` and never set, so the three call sites that force `flow:'paginated'` for fixed-layout books (`ReaderView.vue:769,1078,1157`) never trigger under Reactor.
3. **Gap - fixed-layout spread override (`spread:'none'`) never applied under Reactor.** `useReactor.ts:293-300` accepts `epubOptions`/`fixedLayoutSpread` but never reads it; compare `useFoliate.ts:62-72,301`.
4. **Gap - fixed-layout restore-by-fraction tier skipped under Reactor.** `useFoliate.ts:302-303,328`'s `shouldRestoreByFraction` has no Reactor equivalent.
5. **Gap - media-overlay `mediaOverlaySectionIndex` resume tier missing under Reactor.** `useFoliate.ts:347-349` vs `useReactor.ts` (no such tier).
6. **Gap - `getLocationContext` always returns null under Reactor.** `useReactor.ts:451-454`, affects TTS resume-by-TOC-target UI and any other caller of this method.
7. **Gap - publisher font-size scaling not applied under Reactor.** `scalePublisherFontSizes` is called in `useFoliate.ts:304` but never referenced in `useReactor.ts`.
8. **Gap - swipe-to-turn-page gesture has no Reactor equivalent.** Only tap zones exist under Reactor; foliate supports both tap and swipe (`useFoliateInput.ts:134-146` swipe handling vs nothing in `useReactor.ts`).
9. **Gap - "mobile always toggles chrome" tap heuristic differs under Reactor.** `useFoliateInput.ts:270,286-290` special-cases touch devices; `useReactor.ts:382-398` has no device-type branch, so a touch-device tap in the left/right 30% bands turns a page instead of toggling chrome.
10. **Gap - selection-interaction-start has no Reactor signal.** `setSelectionInteractionStartHandler` is a no-op in `useReactor.ts:138-140`.
11. **Gap - double-tap-same-zone debounce has no explicit Reactor equivalent** (relies on Reactor's own tap/selection disambiguation at the DOM level, unverified from this worktree). `useFoliateInput.ts:256-291` vs nothing explicit in `useReactor.ts`.

Pre-existing foliate-only bug noted in passing (not a Reactor regression,
flagged for its own ticket): foliate's own tap-zone model (`useFoliateInput.ts`)
has no RTL mirroring, unlike Reactor's `shell.resolveTapZone(x, isRtl)`. Not
fixed here since it is out of this card's scope (parity matrix only).

## Recommendation

**Do not flip `VITE_READER_ENGINE=reactor` to default yet.** There is one
confirmed, severe regression (no keyboard page-turn at all under Reactor,
item 1 above) that would break keyboard-only reading and accessibility for
every book, and a second confirmed regression plus three gaps specific to
fixed-layout books (forced-paginated flow, spread override, restore tier,
and no `isFixedLayout` detection at all) that would visibly change behaviour
for any fixed-layout EPUB. Both are small, well-scoped fixes:

- Add a keyboard page-turn handler in `useReactor.ts` (or a small shared
  helper both composables call), wired the same way
  `useFoliateInput.ts:350-383` is today.
- Either have Reactor's `loaded` event report layout type (a Reactor-side
  task, additive per the W1.md protocol-v1-frozen rule), or derive
  `isFixedLayout` web-side from the EPUB's own OPF metadata (BookOrbit
  already parses this server-side for `/api/v1/epub/:bookId/info`) rather
  than from the Reactor event.

Once those two are fixed, the remaining gaps are all either small UX
differences (swipe gesture, double-tap debounce, mobile-tap heuristic) or
already-acceptable per the W1 plan's own standing decisions (TTS primitive,
media-overlay resume heuristic parity, Kobo/KOReader fields computed
web-side). The `untested-needs-owner` items should be run through the owner
checklist above before the flag flip, but none of them block a first
internal/beta flip once the two confirmed regressions are fixed.

**Blockers to flipping the default:**

1. Keyboard page-turn missing entirely under Reactor (regression, item 1).
2. Fixed-layout EPUBs behave differently under Reactor (regression + 3 gaps,
   items 2-4) - at minimum needs an owner decision on whether fixed-layout
   books should force-select the foliate engine until this is fixed,
   independent of the global flag.
